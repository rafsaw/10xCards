## Etap 1 — research infrastruktury

Uruchom skill:

```text
/10x-infra-research
```

Agent powinien bazować na:

```text
context/foundation/tech-stack.md
```

Jeśli czegoś nie wie, odpowiadaj prosto:

```text
nie wiem
```

To jest OK — lekcja podkreśla, że `nie wiem` jest legalną odpowiedzią w tym wywiadzie. 

Typowe pytania agenta:

```text
Czy aplikacja potrzebuje long-running processes / websocketów?
Czy zależy mi na EU region?
Czy to projekt portfolio / open source?
Czy budżet jest mocno ograniczony?
Czy mam preferencję Cloudflare / Vercel / Railway?
Czy baza będzie na tej samej platformie czy zewnętrzna, np. Supabase?
```

Dla Twojego 10xCards prawdopodobnie odpowiedzi mogą być:

```text
No long-running processes for now.
Low cost and good developer experience are both important.
External database: Supabase.
Target deployment: Cloudflare is preferred, but validate alternatives.
Region is not critical for MVP.
No GitHub Actions for now; prefer platform-native deploy.
```

## Etap 2 — nie bierz pierwszej rekomendacji w ciemno

Po researchu agent zrobi scoring platform. W lekcji przykład pokazuje, że Cloudflare Workers może wygrać, ale trzeba jeszcze zrobić testy anti-bias. 

Poproś agenta:

```text
Before we accept Cloudflare, run anti-bias checks:
1. Devil's advocate — why is Cloudflare a bad choice for this project?
2. Pre-mortem — imagine we regret this decision after 3 months. What happened?
3. Unknown unknowns — what risks were not included in the scoring?
```

Potem podejmij jedną z 3 decyzji:

```text
Accept the risk and continue.
Add this risk to infrastructure.md.
Reconsider the platform.
```

## Etap 3 — wygeneruj `infrastructure.md`

Docelowy plik:

```text
context/foundation/infrastructure.md
```

Powinien zawierać:

```markdown
# Infrastructure Decision

## Recommended Platform
Cloudflare Workers / Pages / other selected platform

## Why this platform
Short reasoning.

## Stack Fit
How it fits Astro / React / backend / database.

## Deployment Model
Manual first deploy, then auto deploy from main/master via Cloudflare integration.

## CLI / Agent Fit
Wrangler, GitHub CLI, optional MCP.

## Secrets
Where secrets are stored: Cloudflare secrets, GitHub secrets, Supabase settings.

## Rollback
How to rollback a bad deployment.

## Human Approval Required
Production publish, secret rotation, destructive database actions.

## Known Risks
Cloudflare Node compatibility, free-plan limits, Supabase latency, beta features.

## Decision Change Signal
When to reconsider: long-running jobs, staging env, heavier backend, paid plan, compliance.
```

Lekcja mówi wprost, że `infrastructure.md` jest krótkim kontraktem podobnym do ADR i zostaje w repo jako uzasadnienie decyzji.


```text
Let's plan Cloudflare integration and deployment according to @context/foundation/infrastructure.md and @context/foundation/tech-stack.md.
```

## Etap 7 — przygotuj Supabase

W Supabase:

1. utwórz konto,
2. utwórz projekt,
3. skopiuj:

   * `SUPABASE_URL`
   * publiczny / publishable key,
4. nie używaj `service_role` w frontendzie.

W filmie jest podkreślone, że do aplikacji używasz public/publishable key, a nie secret admin key. 

Lokalnie możesz mieć `.env.example`:

```env
SUPABASE_URL=
SUPABASE_KEY=
```

## Etap 8 — wykonaj deployment fazami

Daj agentowi:

```text
Prerequisites are done. Proceed with Phase 0 of @context/deployment/deploy-plan.md.
Stop after each phase and ask for confirmation before continuing.
```

Typowy flow z lekcji:

```text
Phase 0 — verify repo and prerequisites
Phase 1 — add Cloudflare adapter / runtime changes
Phase 2 — add wrangler config
Phase 3 — verify local build
Phase 4 — configure Supabase secrets
Phase 5 — deploy to Cloudflare
Phase 6 — connect GitHub repo for auto deploy
Phase 7 — verify production app
```

W przykładzie agent zatrzymywał się po fazach i pytał, czy iść dalej — to jest dobry wzorzec, bo nie idzie ślepo naprzód.

## Etap 9 — ustaw sekrety w Cloudflare

Przykład:

```bash
npx wrangler secret put SUPABASE_URL
npx wrangler secret put SUPABASE_KEY
```

Sprawdź listę sekretów:

```bash
npx wrangler secret list
```

Dla Pages może być inna komenda niż dla Workers, więc trzymaj się tego, co wynika z `deploy-plan.md`.

## Etap 11 — ustaw Supabase Auth URLs

Po deploymentcie wejdź w Supabase:

```text
Authentication → URL Configuration
```

Ustaw:

```text
Site URL = publiczny URL z Cloudflare
Redirect URLs = produkcyjny URL + ewentualnie preview URLs
```

W filmie jest ważna uwaga: zrób to zanim testujesz rejestrację użytkownika, bo inaczej linki z maili mogą prowadzić w złe miejsce.

## Etap 12 — opcjonalnie MCP, ale nie na start

Na MVP zacząłbym od CLI:

```text

```

Deep Dive mówi praktycznie: CLI jest dobre, gdy wiesz jaką komendę wykonać; MCP jest dobre, gdy agent ma sam odkrywać, co trzeba zrobić.

## Mój prosty workflow dla kolejnego projektu

Dla każdego nowego projektu rób tak:

```text
1. M1L1 → shape / PRD
2. M1L2 → tech-stack.md
3. M1L3 → scaffold / permissions
4. M1L4 → AGENTS.md jako główny kontrakt dla agentów
5. M1L5 → infrastructure.md + deploy-plan.md + pierwszy deploy
```

Najważniejsza zasada z M1L5:

```text
Nie dodawaj kolejnych ficzerów, dopóki aplikacja nie ma pierwszej ścieżki na produkcję.
```

Czyli dla 10xCards teraz Twoim celem nie jest jeszcze idealna aplikacja. Celem jest:

```text
localhost → Cloudflare → Supabase → publiczny URL
```
