13. Lesson 9 — PR state-driven orchestration

Discovery-only lesson: pytanie badawcze brzmiało, czy om-pr-autopilot stoi nad specialized PR skills i jak z aktualnego stanu PR buduje właściwy workflow.

Finding 016 · ○ documented · ◌ runtime not tested

Core contract — dispatcher above PR capabilities

om-pr-autopilot definiuje jeden entry point dla istniejącego otwartego PR i jawnie deklaruje model diagnose → classify → chain → report. Real work pozostaje w delegated skills; autopilot ma „dispatch, do not re-implement”.

PR→diagnose→classify→chain→delegate→report

Diagnosis — normalized PR State Report

Przed routingiem skill zbiera 10 state signals: identity/repo, PR core, plan progress, diff scope, review/conversations, CI, mergeability, labels, QA evidence i claim state. Nieodczytany sygnał pozostaje unknown — nie staje się assumption.

State matrix — routing is ordered, not single-choice

Rows są oceniane top-to-bottom. Jeden PR może matchować wiele rows, więc autopilot buduje ordered chain: implementation → merge-readiness/review → CI → QA → merge-ready. Po każdym delegated kroku re-czyta cheap signals i pomija lub dodaje dalsze kroki zgodnie z nowym stanem.

Policy — can I vs may I

PUSHABLE odpowiada na pytanie „czy technicznie mogę pushować?”, a DRIVABLE — „czy mam prawo autonomicznie modyfikować ten PR?”. Dzięki temu ten sam technical state może routować inaczej dla własnego PR i PR innego autora.

Human boundaries

Zwykłe odwracalne decyzje są autonomous. Stop conditions obejmują m.in. wrong identity, hard blockers, live foreign claim bez --force oraz ⚠ NEEDS HUMAN CONFIRMATION. Default endpoint to merge-ready; actual merge wymaga --allow-merge.

Repo-driven integration

Preflight ładuje .ai/agentic.config.json, tracker descriptor, repo-local extension oraz agent instructions. Tracker reads/writes idą przez named operations z deskryptora, a nie przez hard-coded GitHub CLI. Repo/tracker content jest traktowany jako data, nie instrukcje.

Reporting is part of the contract

Run publikuje ten sam stan jako PR summary comment i session report: diagnosis on entry, chain executed, state now, labels i verdict. Raport nie może promować niewykonanego gate'u, QA bez evidence, nieudanego label mutation ani nieistniejącego merge'u do stanu „passed”.

Evidence boundary after Lesson 10

Documented: orchestration layer, input contract, 10-signal diagnosis, state matrix, dynamic multi-step chain, delegation boundary, policy guards, repo-specific preflight i reporting.

Not observed: real PR diagnosis, generated runtime chain, chain adaptation after a delegated step, dry-run output, claim collision, QA/CI branches and actual autopilot-directed merge.
