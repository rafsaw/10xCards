Pewnie. M1L1 to w praktyce **fundament projektu**: zanim kodujesz, robisz **shape → PRD**, żeby agent nie implementował losowych założeń.

## M1L1 — step by step guide

### 1. Wejdź do folderu projektu

Dla Twojego 10xCards:

```bash
cd C:\Users\rafal\repos\10xDevs3\10xCards
```

### 2. Zainstaluj helper skille 10x-cli

Najlepiej globalnie, bo będziesz ich używał w kolejnych projektach:

```bash
npx skills add przeprogramowani/10x-cli -g
```

To daje agentowi helpery typu **10x-cli-setup** i **10x-cli-guide**, żeby nie trzeba było pamiętać wszystkich komend ręcznie. 

### 3. Zaloguj się do 10x-cli

```bash
npx @przeprogramowani/10x-cli@latest auth
```

Podajesz email z Circle, klikasz magic link i gotowe. To jednorazowy krok. 

### 4. Pobierz paczkę lekcji M1L1

Dla Claude Code:

```bash
npx @przeprogramowani/10x-cli@latest get m1l1
```

Jeżeli chcesz od razu też dla Cursor:

```bash
npx @przeprogramowani/10x-cli@latest get m1l1 --to cursor
```

Paczka M1L1 zawiera głównie: **/10x-init**, **/10x-shape**, **/10x-prd**. 

### 5. Uruchom `/10x-init`

W Claude Code wpisz:

```text
/10x-init
```

To powinno przygotować strukturę:

```text
context/
  foundation/
```

To jest miejsce na dokumenty decyzyjne projektu.

### 6. Przygotuj krótki pomysł projektu

Możesz stworzyć plik:

```text
context/foundation/idea-notes.md
```

Dla 10xCards wystarczy coś takiego:

```markdown
# 10xCards — idea notes

Chcę zbudować webową aplikację do nauki z fiszek.

Problem:
Manualne tworzenie fiszek jest czasochłonne, więc użytkownik często rezygnuje z nauki metodą spaced repetition.

MVP:
- użytkownik wkleja tekst
- AI generuje propozycje fiszek
- użytkownik akceptuje, edytuje albo odrzuca fiszki
- zaakceptowane fiszki trafiają do systemu powtórek
- użytkownik może rozpocząć prostą sesję nauki

Poza MVP:
- import PDF/DOCX
- mobile app
- własny algorytm spaced repetition
- social sharing
- zaawansowane statystyki
```

### 7. Uruchom `/10x-shape`

```text
/10x-shape @context/foundation/idea-notes.md
```

Tutaj agent będzie Cię przepytywał. To jest najważniejsza część lekcji.

Masz odpowiedzieć na pytania o:

```text
1. Vision & problem
2. Persona & access control
3. MVP discipline
4. Functional requirements + user stories
5. Business logic + data
6. Product framing + non-goals
```

Efektem ma być:

```text
context/foundation/shape-notes.md
```

To nie jest zapis rozmowy, tylko zapis decyzji. 

### 8. Zrób review `shape-notes.md`

Otwórz plik i sprawdź:

```text
Czy persona jest konkretna?
Czy MVP nie jest za duże?
Czy jest pierwszy wartościowy flow?
Czy jest logika biznesowa, a nie tylko CRUD?
Czy są non-goals?
Czy agent czegoś nie dopowiedział za Ciebie?
```

To ważne, bo późniejsze skille będą bazować na tym dokumencie. 

### 9. Wygeneruj PRD

```text
/10x-prd @context/foundation/shape-notes.md
```

Efektem będzie:

```text
context/foundation/prd.md
```

PRD to kontrakt dla dalszych kroków. Nie opisuje jeszcze tech stacku, testów ani deploymentu — to będzie w kolejnych lekcjach. 

### 10. Zrób review `prd.md`

Sprawdź minimum:

```text
Czy jest jeden konkretny użytkownik?
Czy wiadomo, jaki problem rozwiązujesz?
Czy pierwszy flow da się zbudować w ok. 3 tygodnie po godzinach?
Czy logika biznesowa jest konkretna?
Czy non-goals są jasno zapisane?
Czy Open Questions nie zawiera krytycznych luk?
```

Jeśli coś jest słabe — popraw PRD ręcznie albo wróć do `/10x-shape`.

## Najprostszy workflow do zapamiętania

```text
1. cd do projektu
2. npx @przeprogramowani/10x-cli@latest auth
3. npx @przeprogramowani/10x-cli@latest get m1l1
4. /10x-init
5. przygotuj idea-notes.md
6. /10x-shape @context/foundation/idea-notes.md
7. review shape-notes.md
8. /10x-prd @context/foundation/shape-notes.md
9. review prd.md
10. dopiero potem kolejna lekcja / stack / bootstrap
```

## Dla następnego projektu

Zawsze rób to samo:

```text
idea-notes.md → /10x-shape → shape-notes.md → /10x-prd → prd.md
```

Najważniejsza zasada z M1L1: **nie pozwól agentowi kodować, zanim masz kontrakt produktowy.**
