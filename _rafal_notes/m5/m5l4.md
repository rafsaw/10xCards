Możesz testować/używać `rafsaw-ai-toolkit` **bez merge do `main`**, dokładnie na branchu:

```text
learning/m5l4-github-packages
```

Ten branch jest teraz Twoim “consumer sandbox”. Main zostaje czysty, a Ty masz pełny test działania toolkitu.

## 1. Wejdź na branch testowy w `10xCards`

```powershell
cd C:\Users\rafal\repos\10xDevs3\10xCards

git switch learning/m5l4-github-packages
git status
```

Potem sprawdź, czy paczka jest zainstalowana:

```powershell
npm ls @rafsaw/rafsaw-ai-toolkit
```

I czy tool widzi swoje artefakty:

```powershell
npx --no-install rafsaw-ai-toolkit status
```

To jest podstawowy test: **czy toolkit jest zainstalowany i czy manifest działa**.

## 2. Sprawdź, co toolkit dodał

```powershell
Get-Content .claude\.rafsaw-ai-toolkit-manifest.json
```

Powinieneś widzieć listę plików zarządzanych przez toolkit, np.:

```text
.claude/skills/rafsaw-code-review/SKILL.md
.claude/prompts/rafsaw-code-review.md
evals/rafsaw-ai-toolkit.promptfooconfig.yaml
CLAUDE.md
```

Sprawdź też skill:

```powershell
Get-Content .claude\skills\rafsaw-code-review\SKILL.md
```

i prompt:

```powershell
Get-Content .claude\prompts\rafsaw-code-review.md
```

To pokazuje, że paczka nie jest już tylko dependency — realnie dostarczyła artefakty AI do projektu.

## 3. Jak tego użyć praktycznie w Claude Code

W `10xCards` na branchu `learning/m5l4-github-packages` otwórz Claude Code i daj mu prompt typu:

```text
Use the shared rafsaw-code-review skill from .claude/skills/rafsaw-code-review/SKILL.md.

Review the current branch against main:

git diff origin/main...HEAD

Focus on:
- correctness
- CI/CD impact
- package/auth risks
- whether the shared AI toolkit artifacts are safely scoped
- whether secrets are avoided

Return findings grouped by severity:
BLOCKER, HIGH, MEDIUM, LOW, OBSERVATION.
```

To jest najlepszy praktyczny test, bo sprawdzasz, czy agent korzysta z Twoich własnych konwencji review.

Możesz też użyć prompta bezpośrednio:

```text
Use .claude/prompts/rafsaw-code-review.md as the review prompt.

Review the changes introduced by this branch and tell me whether this PR is safe to keep as learning evidence without merging to main.
```

## 4. Test install/uninstall

Ponieważ masz commit, możesz bezpiecznie przetestować uninstall i potem wrócić.

Najpierw:

```powershell
npx --no-install rafsaw-ai-toolkit uninstall
git status
```

Powinieneś zobaczyć, że usunęło pliki zarządzane przez manifest i blok z `CLAUDE.md`.

Potem zainstaluj ponownie:

```powershell
npx --no-install rafsaw-ai-toolkit install
npx --no-install rafsaw-ai-toolkit status
git status
```

Po ponownym `install` stan powinien wrócić do tego, co masz w commicie. Jeśli wszystko wróci poprawnie, to znaczy, że tool ma działający cykl:

```text
install → status → uninstall → install
```

To jest bardzo dobry test M5L4, bo lekcja wymaga nie tylko kopiowania plików, ale kontrolowanej instalacji, aktualizacji i deinstalacji artefaktów AI. 

## 5. Test promptfoo startera

Jeśli chcesz sprawdzić eval starter:

```powershell
npx promptfoo eval -c evals\rafsaw-ai-toolkit.promptfooconfig.yaml
```

Jeśli provider/model nie jest skonfigurowany, ten test może wymagać Twoich zmiennych środowiskowych/API key. Sam fakt, że plik jest dostarczony przez toolkit, jest już OK na poziomie M5L4. Promptfoo możesz dopracować później.

## 6. Najważniejszy realny use case

Dla Ciebie praktyczne użycie toolkitu wygląda tak:

```text
1. W rafsaw-ai-toolkit poprawiasz skill/prompt/rules.
2. Publikujesz nową wersję paczki.
3. W repo-konsumencie robisz:
   npm install --save-dev @rafsaw/rafsaw-ai-toolkit@latest
   npx rafsaw-ai-toolkit install
4. Repo dostaje zaktualizowane artefakty AI.
```

Czyli toolkit jest Twoim prywatnym “AI workflow distribution package”.
